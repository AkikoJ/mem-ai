# 用记忆代次和删除屏障收敛清空竞争

状态为 accepted。清空时可能已有普通任务、显式创建或上游迟到请求正在写入。按用户与提供方建立单调记忆代次，清空先提升代次、暂停该范围记忆读写并取消旧排队任务，旧生成结束时抑制旧代次任务。

所有已发出的旧副作用需要核验，确认收敛后最终清空提供方，再解除屏障。未知上游结果保持待确认并告警。该选择增加操作状态、远程关联及恢复处理，但使清空完成能表示实际外部结果。本地租约隔离状态提交，远程副作用依靠供应商幂等能力、结果核验与最终清空收敛。

会话和用户删除共享这套原则，先阻止业务访问，再异步清理并保留最小远程映射。历史记忆引用标记删除，原始记录遵守会话及用户删除。备份恢复须重放删除和代次记录后恢复写入，供应商核验能力是部署验收的一部分。

2026 年 11 月 21 日补充供应商适配、恢复载体与用户身份边界。其一，当记忆提供方缺乏按单次写入 ID 精确查询状态的能力时，清空屏障不能因单次超时无限期锁死用户记忆：在途旧写入等待其完成或达到可配置的上限收敛窗口（`memory_inflight_settle_timeout`）后，保留 `reconciling` 审计告警并执行最终远程清空与延迟二次补偿清空，确认后解除屏障。其二，备份恢复后的删除重放要求通过独立于主库备份周期的删除审计归档接缝（如对象存储只追加 JSONL 或独立审计卷）承接；若部署未启用独立归档，则以 PostgreSQL PITR（WAL 归档）作为恢复基线并显式标注 RPO 边界。其三，用户删除期间保持 `user_identities` 绑定并拒绝业务访问（`403`），直至本地与远程清理全部确认完成后再删除 `user_identities`，防止删除中未过期外部凭证触发静默重建。
