# 用生成记录和原子提交定义聊天结果

状态为 accepted。聊天可能经历流中断、进程崩溃和响应丢失，模型调用又可能有不可撤销的成本。每次输入保存独立生成记录，使用用户范围幂等键原子关联隐式会话和首次生成，后续同键重试复用原状态及结果。

同一会话使用 PostgreSQL 可续租约及唯一令牌隔离旧执行者，模型与记忆 HTTP 在短事务之外执行。完整回复、生成成功、幂等结果和允许的记忆任务原子提交，流式完成事件在提交后发送。失败或取消的用户输入保留在历史，后续模型上下文仅使用成功回合及当前输入。

这要求维护生成终态、过期恢复及幂等保留边界，客户端通过查询和原键重试恢复。增量只在当前连接内发送，重试成功请求返回已保存完整 JSON。外部模型已经执行而本地未成功提交时，原生成保留失败，用户用新键决定再次生成。

2026 年 11 月 21 日补充租约接管与断连边界。其一，新请求在同一会话领取生成租约时，若发现已有 `running` 回合租约已过期（`lease_expires_at <= now()`），在同一短事务内先将其条件收敛为 `failed`（`generation_lease_lost`）后直接接管，避免 Worker 短暂不可用时会话长期卡死在 `409`；Worker 过期恢复器保留为无后续请求时的兜底。其二，明确区分流式与同步断连：流式请求断连尝试取消上游并将未提交回合标为 `cancelled`，以控制无人消费长流的模型成本；同步请求一旦进入模型执行阶段，不因客户端 HTTP 连接断开而中止，允许在生成期限内继续完成提交，使客户端丢首响应后可通过原幂等键稳定取回完整 JSON。
