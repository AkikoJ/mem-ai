# 17: 接入资源限制与运行观测

**What to build:** 让部署可限制资源并定位生成、记忆和任务故障，提供可运营的 API 与 Worker。

**Blocked by:** [09 持久化任务并重试记忆写入](09-persist-and-retry-memory-writes.md), [12 流式返回与确认生成终态](12-stream-replies-with-terminal-status.md)

**Status:** ready-for-agent

**Parent:** [Mem-AI v1 规格](../spec.md)

## 实现边界

- 扩展 01 的配置、日志、错误及应用生命周期入口，复用已落地的生成、记忆和任务状态来源。
- 资源预算和遥测由 core 公共能力承接，API、SSE 与 Worker 在既有状态转换处记录事件。
- 预算超限、超时与退出通过既有生成和任务收敛入口处理。

## 验收条件

- [ ] 入口分布式限流与应用可替换限制边界明确，应用限制进程并发、请求体、输入、上下文、生成及流时长和 Worker 并发。
- [ ] 预算超限使用稳定 429 及适用重试提示，运行中的生成按状态机收敛，心跳与代理超时配置协调。
- [ ] 生产使用 CORS、Host、可信代理和网关白名单，伪造身份与请求 ID 测试覆盖边界。
- [ ] JSON 日志关联请求、会话、生成和任务，过滤正文、Token、回执和密钥，低基数指标与业务标识分离。
- [ ] 指标覆盖请求和模型延迟、活跃及失败生成、租约、记忆降级、积压、最老等待、待核验、最近成功及屏障时长。
- [ ] 就绪检查包含数据库与迁移兼容版本，Worker 暴露心跳，指标访问受控并预留追踪接缝。
- [ ] 针对性测试验证资源超限、敏感字段过滤、指标状态、依赖故障与优雅退出。
