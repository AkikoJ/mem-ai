# 18: 验证生产部署与恢复流程

**What to build:** 让 V1 在生产配置中完成发布、迁移、恢复和故障演练，形成可执行运行手册。

**Blocked by:** [16 执行数据保留与到期清理](16-apply-data-retention-and-expiry.md), [17 接入资源限制与运行观测](17-add-resource-limits-and-observability.md)

**Status:** ready-for-agent

**Parent:** [Mem-AI v1 规格](../spec.md)

## 实现边界

- 扩展并验收 01 起持续维护的 CI、架构检查、公开行为测试和实际部署入口。
- 迁移、恢复、删除重放和外部核验调用已落地的资源与操作入口，运行手册记录实际命令和证据。
- 核对全部 ticket 的完成记录、公共符号和验证结果，明确剩余部署条件。

## 验收条件

- [ ] API 和 Worker 独立运行，启动、健康检查、任务恢复、优雅停机及连接总预算可在验收环境验证。
- [ ] CI 覆盖 uv 锁一致性、Ruff、mypy、PostgreSQL、空库及历史升级、Alembic 漂移和单元/API/集成测试。
- [ ] 生产真实认证、服务端模型和 MemOS 配置通过有限权限实际接入核验，重点验证分页、幂等、取消及未知结果恢复能力。
- [ ] 发布采用 expand、migrate、contract，单执行者迁移并校验兼容版本，手册明确失败后的前向修复与兼容应用回滚。
- [ ] 备份及恢复演练记录时间点、可接受数据损失、RPO/RTO、角色和检查点，数据库恢复作为独立恢复操作。
- [ ] 备份恢复演练覆盖两种分层基线：启用独立删除审计归档时，暂停写入并通过工具重放备份时间点之后的删除与代次记录再恢复服务；仅使用 PostgreSQL PITR 时，按 WAL 归档恢复并显式记录 RPO 与删除一致性边界。
- [ ] 手册覆盖密钥注入与轮换、TLS/代理、入口限流、资源预算、任务耗尽、待核验结果和长期屏障告警处置。
- [ ] 对全部 V1 契约做公开入口验收，工程目录、环境模板、工作流和操作手册与最终文件一致，记录实际执行结果和剩余部署条件。
