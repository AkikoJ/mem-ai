# 05: 发起和继续同步对话

**What to build:** 让用户通过聊天入口隐式创建或继续会话，得到完整同步回复，并可在模型失败后保留真实历史。

**Blocked by:** [03 创建和使用私有 Agent](03-create-and-use-private-agent.md)

**Status:** ready-for-agent

**Parent:** [Mem-AI v1 规格](../spec.md)

## 实现边界

- 复用 03 的生命周期实现和 PersonaProvider，通过 models 解析默认模型并调用项目 ModelProvider。
- 本切片建立工程设计第 5.4 节的共同生成编排与持久化阶段，统一用户消息准备、成功提交和失败收敛。
- 07、08、09、10、12、13 分别扩展相同入口的租约、召回、入队、幂等、SSE 和代次检查，Prompt 编译使用纯项目数据。

## 验收条件

- [ ] 省略 conversationId 时创建会话并固定最新发布版本，成功返回会话、生成、回复 ID、实际模型及用量。
- [ ] 继续会话使用固定人设，近期成功回合和当前输入进入 Prompt，失败及取消回合的用户消息留存但从后续 Prompt 过滤。
- [ ] 无发布版本、Agent 与会话不匹配、跨用户资源及不可用默认模型在外部调用前拒绝。
- [ ] 生成记录从 running 转为 succeeded 或 failed，调用模型之前提交原始用户消息。
- [ ] 准备、上下文、成功提交及失败收敛具有共同入口，完成记录列出后续租约、幂等和 SSE 切片应扩展的实际符号。
- [ ] 完整 Assistant 回复与生成成功在同一短事务提交，普通记忆任务在任务切片接入后加入同一事务。
- [ ] 准备阶段在数据库事务外通过只读 `PersonaProvider` 解析人设快照，短事务中固定版本引用与原始用户消息；同步请求进入模型调用后不因客户端 HTTP 断连而中止，保证提交后可通过原幂等键取回完整结果。
- [ ] 模型 HTTP 期间释放数据库事务，提交失败、模型超时、上游错误均留下稳定可恢复状态。
- [ ] 服务端注册的兼容接口模型适配器通过项目 ModelProvider 实际完成完整生成，受控上游验证响应、用量、超时及失败映射。
- [ ] 路由测试和 PostgreSQL 集成测试覆盖新会话、续聊、失败历史过滤、资源隔离及原子提交。
