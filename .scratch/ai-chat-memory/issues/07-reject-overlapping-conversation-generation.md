# 07: 控制同一会话的并发生成

**What to build:** 让同一会话保持单个活跃生成，不同会话并行，并在进程故障后恢复生成资格。

**Blocked by:** [05 发起和继续同步对话](05-start-and-continue-sync-chat.md)

**Status:** ready-for-agent

**Parent:** [Mem-AI v1 规格](../spec.md)

## 实现边界

- 扩展 05 的 generation 阶段入口，为准备、续期、终态和释放加入同一组令牌条件。
- 过期恢复调用共同失败收敛入口，后续 Worker 复用该操作。
- 生成租约保护生成提交资格，09 的任务租约保护任务执行状态，两类资源分别维护。

## 验收条件

- [ ] 主动暂停模型并从独立数据库会话发起竞争，第二个不同生成立即返回 409 conversation_generation_conflict。
- [ ] 竞争失败请求不追加用户消息或调用模型，不同会话可同时完成。
- [ ] PostgreSQL 租约具备期限、唯一所有权令牌及续期，成功、失败和超时释放资格。
- [ ] 续期、回复写入、终态与释放均校验令牌、有效期及用户和会话状态，旧执行者失去提交资格。
- [ ] 新请求领取租约时若发现旧 `running` 回合租约已过期（`lease_expires_at <= now()`），在同一短事务内先将其收敛为 `failed`（`generation_lease_lost`）后直接接管，不依赖 Worker 存活；Worker 过期恢复器作为无后续新请求时的兜底。
- [ ] 同步和流式共用生成入口，数据库事务保持短时，进程崩溃、续期失败及旧执行者恢复有 PostgreSQL 测试。
