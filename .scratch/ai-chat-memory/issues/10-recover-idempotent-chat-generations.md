# 10: 支持聊天幂等与生成结果查询

**What to build:** 让客户端安全重试聊天并找回原生成，首次响应丢失时也能恢复隐式创建的会话。

**Blocked by:** [07 控制同一会话的并发生成](07-reject-overlapping-conversation-generation.md)

**Status:** ready-for-agent

**Parent:** [Mem-AI v1 规格](../spec.md)

## 实现边界

- 扩展 05、07 的生成准备与终态事务，幂等占位和结果更新显式参与该阶段 Session。
- idempotency 统一负责摘要与原结果解析，查询读取已有生成数据，后续 SSE 重试复用相同入口。
- 同键请求先解析已有结果再竞争租约，原请求恢复使用已有生成与固定配置。

## 验收条件

- [ ] 聊天必填 Idempotency-Key，唯一范围为 user_id、HTTP 方法、规范路由和键，业务摘要包含 Agent、会话缺省标记、消息、请求模型等参数。
- [ ] stream 不参与摘要，首次选定的人设和模型固定保存，配置变化后的重试复用原生成。
- [ ] 幂等占位、隐式会话、生成和用户消息原子关联，同键并发只创建一份并只调用一次模型。
- [ ] 同键同摘要的 running 返回 202 和原 IDs、查询地址，成功统一返回已保存的 200 JSON，失败及取消返回原终态与稳定错误。
- [ ] 同键异摘要返回 409 idempotency_key_conflict，幂等记录读取先于租约争用，失败后新键可再生成。
- [ ] 生成查询验证用户归属、会话和用户当前状态，返回运行或终态、成功结果及错误，删除后的资源遵守统一策略。
- [ ] 终态幂等自 terminal_at 保留 24 小时，活跃记录持续保留，生成独立按会话保留策略保存。
- [ ] 路由及数据库测试覆盖同键并发、丢响应、stream 切换、摘要冲突、跨用户、租约恢复、到期边界和已删除资源。
