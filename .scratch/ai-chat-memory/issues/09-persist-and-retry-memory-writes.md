# 09: 持久化任务并重试记忆写入

**What to build:** 让完整回合的记忆写入可靠落到后台，即使进程重启仍可重试或核验外部结果。

**Blocked by:** [04 查看和显式添加长期记忆](04-list-and-explicitly-create-memories.md), [05 发起和继续同步对话](05-start-and-continue-sync-chat.md)

**Status:** ready-for-agent

**Parent:** [Mem-AI v1 规格](../spec.md)

## 实现边界

- 扩展 04 的统一 jobs 记录与执行结果入口，记忆处理器复用既有适配器和范围策略。
- 通过 05 的成功提交阶段在同一 Session 入队，memory_jobs 作为 jobs 的只读视图管理。
- jobs 负责领取、租约、重试和任务状态，memories/jobs.py 负责业务副作用，runner 负责注册与并发调度。

## 验收条件

- [ ] 完整回复、生成成功和普通记忆任务在同一短事务提交，入队失败整体回滚，关闭记忆写入时只提交回复及状态。
- [ ] 失败和取消回合不创建完整回合任务，上游记忆失败保持已提交回复成功。
- [ ] 统一 jobs 表以 job_type 注册业务处理器，memory_jobs 为只读查询视图，执行摘要具有独立保留时间。
- [ ] 独立 Worker 使用 SKIP LOCKED、租约和令牌条件提交，支持可配置并发、指数退避、抖动、最大尝试和优雅退出。
- [ ] 稳定任务 ID 和去重键防重复入队，上游使用幂等或结果核验，响应丢失进入 reconciling 并留下关联信息。
- [ ] 租约过期重新领取时旧执行者无法覆盖状态，未知上游结果保持可核验并告警。
- [ ] 任务状态、重试、下一次执行及错误摘要可查询或观测，日志过滤正文、Token 和密钥。
- [ ] PostgreSQL 测试验证原子提交、重启、重复领取、失败耗尽、未知结果和退出恢复，框架可供删除及周期处理器复用。
