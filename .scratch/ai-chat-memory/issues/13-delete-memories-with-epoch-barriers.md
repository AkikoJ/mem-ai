# 13: 删除与清空记忆并阻止旧任务回写

**What to build:** 让用户删除单条或清空记忆，立即停止相关召回，并通过可查询操作确保旧写入最终收敛。

**Blocked by:** [04 查看和显式添加长期记忆](04-list-and-explicitly-create-memories.md), [08 召回相关范围的记忆](08-recall-relevant-scoped-memories.md), [09 持久化任务并重试记忆写入](09-persist-and-retry-memory-writes.md)

**Status:** ready-for-agent

**Parent:** [Mem-AI v1 规格](../spec.md)

## 实现边界

- 扩展 04、08 的 memories 策略和 09 的记忆处理器，统一拥有代次、屏障、删除标记及写入资格检查。
- operations 提供操作创建、进度和终态入口，jobs 承担任务执行规则，资源处理器通过这些入口报告结果。
- 对话成功提交通过同一策略检查旧代次入队资格，14、15 继续复用该策略完成范围清理。

## 验收条件

- [ ] 单条删除与 confirm=true 清空先保存删除操作，确认完成返回 204，执行中或结果待确认返回 202、operationId 和查询地址。
- [ ] 操作查询返回 pending、running、reconciling、succeeded 或 failed，确定失败映射稳定错误，其他用户读取返回 404。
- [ ] 单条删除建立 tombstone，之后召回过滤该记忆，历史引用保留并标为删除或无法解析。
- [ ] 清空以用户和提供方范围原子递增 epoch、建立屏障并取消旧代次排队任务，生成和写入捕获代次，在途写入登记与清空使用相同范围锁串行。
- [ ] 屏障中召回降级为空，显式创建返回 409 memory_scope_clearing，新普通写入暂停，旧生成完成时抑制其旧代次任务。
- [ ] 显式创建和普通任务的在途外部写入均登记与核验，迟到或未知结果保持屏障待确认，旧写入收敛后最终清空并解除屏障。
- [ ] 删除处理器复用统一任务框架，使用稳定操作关联和提供方结果核验，重复执行可恢复。
- [ ] 受控上游及 PostgreSQL 测试覆盖排队、已发送写入、丢响应、迟到完成、显式创建竞争、旧生成收尾和重启恢复。
