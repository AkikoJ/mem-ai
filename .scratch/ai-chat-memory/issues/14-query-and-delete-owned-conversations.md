# 14: 查询与删除自己的会话

**What to build:** 让用户查看自己的会话及真实消息历史，并删除会话与相关会话记忆。

**Blocked by:** [07 控制同一会话的并发生成](07-reject-overlapping-conversation-generation.md), [09 持久化任务并重试记忆写入](09-persist-and-retry-memory-writes.md), [13 删除与清空记忆并阻止旧任务回写](13-delete-memories-with-epoch-barriers.md)

**Status:** ready-for-agent

**Parent:** [Mem-AI v1 规格](../spec.md)

## 实现边界

- 复用 conversation 的归属规则、07 的生成条件提交、09 的任务框架和 13 的删除操作与记忆策略。
- conversations/cleanup.py 负责会话数据分批清理，远程会话记忆通过 memories 的范围清理入口处理。
- 会话 deleting 状态与范围删除标记参与写入校验，用户级代次与用户级记忆遵循既有清空契约。

## 验收条件

- [ ] 会话列表、详情和消息历史采用统一游标，包含生成状态，可区分失败或取消回合与完整回复。
- [ ] 删除立即将会话置为 deleting 并阻止续聊，返回可查询操作，其他用户操作统一 404。
- [ ] 后台分批清理消息、召回引用、生成、相关幂等及该会话范围记忆，用户记忆按用户级清空规则保留。
- [ ] 在途生成最终提交检查会话状态，既有任务在执行前复查，已发外部写入核验并在最终会话清空前收敛。
- [ ] 会话清理使用统一任务、去重和租约，重复删除关联同一有效操作，重启后继续，全部确认才完成。
- [ ] HTTP 和 PostgreSQL 测试覆盖分页、用户隔离、生成竞争、任务竞争、远程未知结果、重复请求和分批恢复。
