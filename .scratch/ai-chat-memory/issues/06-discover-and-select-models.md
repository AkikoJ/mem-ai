# 06: 查询和选择可用模型

**What to build:** 让用户查询可用模型，并在服务端策略允许时覆盖 Agent 默认模型。

**Blocked by:** [05 发起和继续同步对话](05-start-and-continue-sync-chat.md)

**Status:** ready-for-agent

**Parent:** [Mem-AI v1 规格](../spec.md)

## 实现边界

- 扩展 05 已使用的模型选择入口，模型列表与聊天选择使用相同的启用、权限及能力规则。
- 注册配置和供应商连接由 models 管理，生成准备阶段保存实际选择结果。
- 同步和后续流式请求通过同一模型策略决定能力与默认值。

## 验收条件

- [ ] 模型查询只公开当前用户可用且启用的注册标识与能力，凭据及供应商内部连接配置保持服务端管理。
- [ ] 路由优先级依次为服务端强制策略、被允许的请求模型、Agent 默认模型，省略模型复用 Agent 默认。
- [ ] 注册模型、默认模型及能力通过服务端受控配置在启动或显式同步命令中幂等写入 `model_configs`，配置缺失返回稳定配置错误。
- [ ] 未注册、停用、越权或不具备请求能力的模型在上游调用前拒绝；旧会话固定人设快照引用的默认模型已停用且请求省略 `modelId` 时返回稳定错误 `model_unavailable`，策略允许时调用方可显式传入其他已启用 `modelId` 继续。
- [ ] 选定模型失败得到该次生成失败，测试断言调用的模型、次数和实际保存的 modelId。
- [ ] 请求 API Key、Base URL 和任意供应商配置被 Schema 拒绝。
