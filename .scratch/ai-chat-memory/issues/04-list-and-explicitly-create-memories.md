# 04: 查看和显式添加长期记忆

**What to build:** 让认证用户查看并同步显式添加自己的长期记忆，通过可替换 MemOS 适配器获得确定的创建结果。

**Blocked by:** [02 接入认证上下文和用户主体](02-connect-auth-context-and-user-subject.md)

**Status:** ready-for-agent

**Parent:** [Mem-AI v1 规格](../spec.md)

## 实现边界

- 复用认证、分页及项目 MemoryProvider 契约，MemOS 协议集中在 memories 适配器。开始本切片实现前先完成一次 MemOS Cloud 真实接口最小能力验证（同步模式返回、状态查询、`tags`/`info` 过滤、删除收敛延迟）并记录结论。
- 稳定写入登记从统一 jobs 建立最小持久化与执行结果入口，09 在原表和入口扩展 Worker、租约与重试。
- 范围解析由 memories 提供（显式创建默认 `user`，可选 `conversation` 并校验会话归属），08 的召回、09 的普通回合写入和 13 的删除屏障扩展同一策略。

## 验收条件

- [ ] 列表和显式创建通过公开路由验证，范围由认证用户确定，显式创建默认为用户级记忆，指定 `conversation` 时校验会话归属。
- [ ] 提供方同步确认并返回稳定单条 ID 时返回 201；若提供方（如异步抽取型适配器）仅受理而尚未产出单条 ID，返回 202 与可查询 `operationId`；已知失败映射稳定应用错误。
- [ ] 显式创建通过统一 jobs 的最小持久化入口保存稳定写入标识、目标范围和外部结果关联，请求路径同步领取执行，超时未知保留可核验信息供共享 Worker 和删除屏障接入。
- [ ] 列表统一游标契约，默认 20、上限 100；对仅支持页码分页的供应商，有界分页快照持久化到 PostgreSQL `memory_list_snapshots` 表以支持多副本部署，适配器契约测试验证稳定 ID、排序、跨页、过期游标及用户隔离。
- [ ] MemOS HTTP、鉴权及响应映射封装在 MemoryProvider 实现中，受控上游覆盖成功、超时和失败，凭据来自服务端。
- [ ] 其他用户记忆无法列出或新增到其名下，错误和日志过滤供应商凭据及用户正文。
