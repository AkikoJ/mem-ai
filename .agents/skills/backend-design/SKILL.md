# 后端设计与目录维护

## 项目入口

从项目根目录读取 `AGENTS.md` 和 `docs/backend-scaffold-design.md`。涉及业务或架构职责时，再读取 `DESIGN.md`、`GLOSSARY.md` 和相关 ADR。

工程目录以 `docs/backend-scaffold-design.md` 第 3 节为维护入口。区分设计阶段的计划条目和已经落地的结构，依据任务范围与实施阶段更新。

## 设计目录

- 每个展示的文件和目录都在同一行附加简短的用途注释，包括根目录、容器目录、配置、测试与工作流。
- 注释说明实际负责的能力、管理的资源或调用入口，并区分同名文件在不同层级中的职责。
- 按业务模块组织目录，公共模块和模块内部文件的说明保持一致。
- 通用模块模板中的每个文件也标注用途，按实际需要列出文件。
- 将目标目录、文件职责表和正文中的路径引用一起核对。

## 文件变更后的同步检查

新增、修改、移动、重命名或删除后端文件、配置、测试、工作流及本技能文件时，在交付前执行以下检查。

1. 查看本次变更清单，包含未跟踪文件，定位受影响的工程目录和用途说明。
2. 对每个变更判断路径、父子层级或职责是否发生变化。修改内容同样需要检查用途描述是否准确。
3. 按实际差异同步文档。
   - 新增条目时补充所在位置与用途。
   - 移动或重命名时同步路径、层级及引用。
   - 职责变化时改写注释、职责表和相关正文。
   - 删除条目时清理目录记录、失效说明和路径引用。
   - 调整计划结构时标明计划状态，并与实施阶段协调。
4. 对照实际文件和已确认的目标设计，复核每条注释、相对链接及相关模块模板。

仅内容变化的文件，通过路径、层级和职责核对后决定是否需要调整目录说明。文档描述范围以对应工程目录为准，保留任务开始前已有的其他工作。

## 完成条件

展示的每个目录树条目都有用途注释，本次文件变更已逐项完成同步判断，受影响的目录、职责说明和引用相互一致。验证遵循项目已有的命令执行约定。
